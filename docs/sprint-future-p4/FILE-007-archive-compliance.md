## 1. 概述

企业客户「项目结束」不等于「可以归档」：未结任务、未释放的法务保留、进行中的审批都是归档阻断项。无强制检查的归档会让归档变成数据丢失事故的温床（归档后只读，问题无法修复）。

| 交付项 | 说明 |
| --- | --- |
| 归档前置检查器 | 归档请求先过合规闸门：未结任务/活跃 LegalHold/进行中审批 → 409 阻断并列明清单 |
| 合规报告 | 归档时刻组织快照（任务统计/成员清单/工时汇总）留档可导出 |

## 2. 业务规则（BR）

| 编号 | 规则 | 说明 |
| --- | --- | --- |
| BR-01 | 阻断性检查 | 存在未结任务（非终态）→ 409 `RESOURCE_STATE_INVALID` + details 列明（前 20 条）；活跃 LegalHold 同阻断 |
| BR-02 | 警告性检查 | 无负责人任务、未来日期任务 → 警告清单（不阻断，`?force=true` 仍可归档） |
| BR-03 | 快照留档 | 归档成功即生成合规报告（任务计数/成员/工时），不可编辑 |
| BR-04 | 审计 | 归档检查与归档动作均入 AuditLog |

## 4. 技术架构

服务 `ArchiveComplianceService.check(workspace)` 返回 `{blocking: [...], warnings: [...], stats: {...}}`；挂接 TEAM-003 archive 端点前置。报告模型 `ArchiveComplianceReport(workspace, snapshot JSONB, archived_at)`。

## 5. 测试用例（核心）

| 编号 | 用例 | 断言 |
| --- | --- | --- |
| UT-01 | 未结任务阻断 | 有未结任务 → blocking 非空；终态后 → 通过 |
| UT-02 | LegalHold 阻断 | 活跃保留阻断；释放后通过 |
| UT-03 | 警告不阻断 | 无负责人任务 → warnings；force 通过 |
| UT-04 | 报告快照 | 归档后报告含任务计数与成员数 |
