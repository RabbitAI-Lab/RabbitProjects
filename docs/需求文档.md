# 复刻Ones/Plane企业级项目管理系统 完整需求文档\&功能清单（React Router\+Django\+PostgreSQL全栈，技术栈与Plane开源版完全一致）

## 一、项目概述

### 1\.1 项目定位

复刻 Ones、Plane 开源企业级项目管理平台，打造一套支持**个人/团队/企业**使用的全功能项目协作系统，覆盖任务管理、看板、甘特图、文件协作、实时沟通、权限管控、第三方工具集成全能力，对标主流轻量化研发项目管理工具，兼顾轻量化个人使用与规范化企业团队协作场景。

### 1\.2 技术栈固定（严格执行，与 Plane 开源版完全一致）

开源参考：https://github\.com/makeplane/plane（技术选型与其 master 分支保持一致）

- 工程结构：pnpm workspace \+ Turborepo Monorepo（apps/ 承载全部应用、packages/ 承载共享包），Docker Compose 编排全套服务

- 前端框架：React Router v7（Framework Mode，Vite 构建，TypeScript 全类型）；三个前端应用：web 主工作台、admin 实例管理后台（God Mode）、space 对外公开空间

- 后端框架：Django \+ Django REST Framework（Python，RESTful API 服务）

- 异步任务：Celery（worker \+ beat 双进程）\+ RabbitMQ 消息队列

- 数据库：PostgreSQL 14\+（生产镜像 postgres 15\.7），Django ORM \+ Django migrations 自动迁移

- 缓存：Redis（Valkey 7\.x 兼容）

- 实时协作：独立 Node\.js live 服务（Express \+ WebSocket），Hocuspocus \+ Yjs CRDT 驱动富文本/文档多人协同

- UI 体系：Tailwind CSS \+ Headless UI \+ 自研组件库（@plane/ui 模式）\+ lucide\-react 图标

- 状态管理：MobX（mobx \+ mobx\-react）；数据请求：SWR \+ Axios

- 富文本：Tiptap（ProseMirror）封装自研编辑器包（@plane/editor 模式），承载任务描述与协作文档

- 拖拽/表格/图表：@atlaskit/pragmatic\-drag\-and\-drop、TanStack Table、recharts

- 认证：Django 自研认证（Session \+ Token \+ OAuth），不使用 NextAuth

- 文件存储：MinIO / S3 兼容对象存储，预签名直传

- 反向代理：Nginx（apps/proxy）统一路由 web / admin / space / api / live

- 环境要求：Node\.js 20\+、Python 3\.8\+、PostgreSQL 14\+、Redis 6\.2\+

- 代码质量：OxLint \+ oxfmt \+ Husky；前端 TS 强类型，后端 Python 类型注解

### 1\.3 用户角色体系（固定）

系统内置三类核心角色，权限逐级隔离，支持多层级资源管控：

- **系统管理员**：全局最高权限，管理全站用户、系统配置、存储策略、集成全局配置

- **团队管理员**：管理所属团队、团队项目、团队成员、项目权限、自定义流程

- **普通成员**：参与项目、创建/跟进任务、协作评论、上传文件，无管理权限

## 二、整体功能总览（全量清单，无遗漏）

系统分为 9 大核心模块，同时区分**标准版（个人/小团队）**与**企业版（中大型团队/企业）**双层能力体系；九大模块：系统账号权限、团队管理、项目管理、任务核心管理、看板视图、甘特图进度、文件资源管理、实时协作通知、第三方工具集成，额外增补企业专属管控、合规、自动化、报表、组织治理、高级集成全套企业能力。

#### 3\.4\.1 统一工作项模型（需求/缺陷/任务统一载体）

**核心设计决策：系统不单独建设独立的「需求模块」，所有需求、缺陷、开发任务、测试项、文档工作均通过统一的「工作项（系统内统一称任务/Issue）」承载，通过「任务类型」字段做区分，完全对齐 Plane/Ones 的统一工作项设计。**

- 设计原因1：避免需求、任务、缺陷各建一套数据模型导致的重复开发与数据割裂，一套底层能力支撑所有工作类型

- 设计原因2：需求可直接拆解为开发任务、关联提测任务与缺陷，全链路自动打通，无需跨模块同步数据

- 设计原因3：看板、甘特图、筛选器、工作流、统计报表、权限体系全部复用同一套能力，降低开发与维护成本

- **需求录入方式**：新建工作项时将「任务类型」选择为「需求」即可完成需求录入，系统内置需求/缺陷/任务/测试/文档5种默认类型，团队管理员可自定义新增、改名、停用类型

- 类型差异化配置：每种任务类型可独立配置专属字段模板、默认状态集、独立工作流、图标颜色、必填规则；例如需求类型可配置「需求来源、业务价值、所属迭代、验收标准」等专属字段，缺陷类型可配置「严重等级、复现步骤、影响版本」，不同类型字段互不干扰

- 需求池专项能力：提供独立的「需求池」内置视图，默认筛选「任务类型=需求」，支持需求评审、需求排期、需求一键转任务（将需求拆解为多个开发子任务并自动保留父子关联）、需求版本规划与需求统计

- 迭代落地节奏：P1支持任务类型切换与基础类型区分；P2支持类型专属字段模板、需求一键转任务；P3企业版支持按任务类型绑定独立审批工作流

#### 3\.4\.2 动态自定义字段与全字段筛选体系

**明确结论：完整支持任务字段动态增减，新增/删除字段无需修改数据库表结构、无需发版；且所有内置字段\+自定义字段均自动支持筛选、排序、分组。**

##### （1）动态字段能力分层

- 字段可视化管理：团队/项目管理员可在设置后台可视化新增、编辑、停用、删除、拖拽排序自定义字段，配置后立即在任务新建弹窗、任务详情、看板卡片、所有视图中生效

- **标准版（P2迭代交付）支持基础字段类型**：单行文本、多行文本、整数/小数数字、单选下拉、多选下拉、日期、人员单选、人员多选、复选框、URL链接、金额、自增编号

- **企业版（P3/P4迭代交付）支持高级字段类型**：级联下拉选择、关联其他工作项、日期区间、公式自动计算字段、附件字段、字段级权限（只读/隐藏/按角色必填）、字段联动显隐、跨项目关联字段

- 字段作用域控制：可配置字段仅对哪些任务类型、哪些项目生效，支持设置默认值、必填规则、选项颜色、字段帮助说明

- 技术实现方案：PostgreSQL采用「字段配置表 \+ 任务表JSONB扩展字段列」实现，内置高频字段存主表保证查询性能，自定义字段值统一存入 `customFields` JSONB列并建立GIN索引，兼顾灵活性与查询性能，新增/删除字段不需要执行数据库DDL改表操作

##### （2）全字段筛选器能力

- 全字段覆盖：所有内置字段与所有自定义字段均可作为筛选条件，系统自动匹配字段类型渲染对应筛选控件（单选下拉、日期区间、人员选择器、数字区间、文本模糊匹配等）

- 复杂逻辑支持：支持多条件AND/OR逻辑组合、条件分组嵌套、筛选条件一键清空、最近使用筛选快速复用

- 排序与分组：筛选结果支持按任意字段（含自定义字段）排序、按任意字段分组统计

- 视图联动：筛选配置可保存为个人视图或团队共享视图，列表、看板、甘特图、表格四大视图共用同一套筛选器体系

- 三层筛选层级：支持全局跨项目筛选、项目内全量筛选、视图内临时筛选，筛选条件可叠加

##### （3）迭代优先级对齐（与整体排期严格一致）

- **P0（POC阶段）**：不做动态字段，仅写死标题、描述、状态、负责人、截止时间5个核心内置字段，保证最小闭环2周交付，不扩散需求

- **P1（MVP阶段）**：支持内置固定字段（优先级、任务类型、标签）的基础筛选、关键词搜索、简单排序

- **P2（标准版）**：完整交付基础自定义字段动态增删管理、全字段AND/OR组合筛选器、筛选保存为视图、自定义字段排序与分组

- **P3（企业版核心）**：交付高级字段类型、字段级权限、字段联动显隐、按任务类型/项目控制字段显隐

- **P4（远期增强）**：公式计算字段、多级级联字段、跨项目关联字段、字段全变更审计

#### 3\.4\.3 核心疑问统一收口（需求录入 \& 动态字段能力定论）

**1、任务字段是否支持动态增减、筛选器联动？（最终落地结论）**

系统**完全支持任务字段动态增减**，全程无需改数据库表结构、无需版本发版，管理员后台可视化配置即可生效，且严格遵循迭代优先级落地：POC固定核心字段保证交付，标准版上线完整动态字段能力，企业版补齐高阶字段与权限能力。所有自定义字段**自动全局联动筛选器、排序、分组、视图保存**，列表/看板/甘特图/表格视图统一复用同一套字段与筛选规则，无视图能力割裂。

字段能力迭代收口：

- POC阶段：仅固定5个核心内置字段，不做动态字段，保障最小闭环快速交付

- MVP阶段：内置业务字段（类型/优先级/标签）支持基础筛选排序

- 标准版P2：完整开放基础自定义字段动态增删、全字段组合筛选、视图联动能力（生产可用）

- 企业版P3/P4：高阶字段、字段权限、字段联动、公式级联等高级能力

**2、业务需求是否通过任务录入？（统一业务模型定论）**

全系统统一收口：**所有业务需求、用户需求、迭代需求、缺陷、开发任务、测试项，全部统一通过「任务/工作项」录入，无独立需求模块**，完全对齐Ones/Plane主流研发管理模型。

业务需求落地方式：用户新建任务时，将「任务类型」选择为【需求】，即为标准需求录入，归属项目、可配置专属需求字段、可进入需求池视图、可评审排期、可一键拆解子开发任务、可全链路追溯。该模型彻底打通「需求→拆解任务→开发→测试→缺陷→交付」全链路，数据统一、无需跨模块同步，大幅降低维护成本。

**需求专属能力补充**：

- 独立需求池视图：自动筛选全部「需求类型」工作项，单独做需求管理入口

- 需求差异化字段：需求类型可单独配置专属字段（需求来源、业务价值、用户场景、验收标准、所属迭代、优先级层级），与缺陷、任务字段隔离互不干扰

- 需求流转差异化：企业版可单独给「需求类型」配置独立评审工作流，实现需求评审、驳回、定稿闭环

- 需求拆解能力：支持需求一键拆解为多个子任务，自动建立父子关联，实现需求到落地的全链路追溯
