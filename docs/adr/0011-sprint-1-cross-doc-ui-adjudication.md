| 背景 | sprint-1 12 份文档全部通过 5 维度评审（≥9.5）后，跨文档 UI 走查发现 11 处文档间矛盾（同一表面两份文档描述不一致）与 9 处规格空缺（任何文档都未定义）。矛盾集中在任务详情抽屉结构、项目壳形态、通知中心形态、优先级色值、搜索参数名等跨消费方表面 |

| 后果 | ① 抽屉 Tab 条 / 项目壳冻结形态 / 通知抽屉成为唯一口径，后续实现与 parity 清单以此为基准；② #11 搜索参数统一为 `?q=` 与 `api-conventions.md` §5.5「列表内搜索 `?search=`」存在偏差——**架构文档待回改**（§5.5 列表内搜索参数改 `q`，全局搜索 `?q=` 不变），回改前以本 ADR 为准；③ 交付物 UI 表面如需进 e2e parity 清单，按 ADR-0010 纪律补登记 |
