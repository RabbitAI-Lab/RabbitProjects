## 二、TASK-011 后端（T3-07）

| 条款号 | 偏差 | 理由 | 影响面 |
| --- | --- | --- | --- |
| §1.2 / §4.3.1 | **空 `conditions`（`{"op":"and","conditions":[]}`）合法化**为无操作（等价无筛选） | 面板「清空全部条件」天然产生空树；拒 400 会逼前端特判删除根节点 | 空 DSL 与缺省 `filters={}` 行为一致；深度/节点校验对空树放行 |
| §2.3 | `priority` / `state` / `issue_type` / `parent` 四个内置字段的操作符**收窄为 `{in, not_in}`** | 枚举/FK 族语义上只有集合隶属判定有意义；通用操作符表按类型收窄是编译器白名单的自然收口 | 传其他操作符 400 `VALIDATION_INVALID_PARAM`；与 §2.3 表内 `state` / `priority` 行一致，`issue_type` / `parent` 行随勘误补记 |
| §2.3 注 | `labels` 操作符集**取 member 族并集**（`in` / `not_in` / `contains_any` / `contains_all` / `is_empty`） | labels 为多值关联字段，与 `member_multi` 同构，复用同一编译分支 | 前端控件与 member 同款；值域校验按标签 UUID |
| §2.3 / §4.3.2 | 自定义字段**否定操作符（`neq` / `not_in` / `not_contains`）含未填行**（语义 = `NOT(has_key AND 正值判定)`，未填 key 的行命中否定条件） | 「不等于 X」的自然语言语义包含「根本没填」；若排除未填行，用户需手工叠加 `is_not_empty` | 仅 cf 族（JSONB 判存）；内置字段空值语义不变（规格未定义 cf 否定与空值的交，本条为补定义） |
| §4.2.2 / BR-17 | `meta.applied` 的**结构化键（`filters_signature` 等）仅当请求带 `?filters=` 参数时附加**；`?view_id=` 与无参请求不附加 | **无参响应逐字节不变**是既有消费者（BOARD-002 分组端点、e2e 快照）的红线；`?filters=` 是 TASK-011 新入口、无存量依赖 | BR-17 的「回显生效条件」仅对显式传 DSL 的请求生效；视图消费路径靠 `?view_id=` 时 applied 以视图存档为准（前端另经视图详情展示） |

## 三、BOARD-004 后端（T3-08）

| 条款号 | 偏差 | 理由 | 影响面 |
| --- | --- | --- | --- |
| §4.2.1 | 批量更新 PATCH 请求体**恰好一个动作字段**（status / priority / assignees / labels 互斥，混传 400） | 混合动作使失败语义与 Activity 留痕粒度不可定义（哪部分回滚？）；规格示例本就单动作 | 混传 `400 VALIDATION_INVALID_PARAM`；需多动作由前端顺序发起（每动作独立事务与 epoch） |
| §4.2.4 | 危险动作预检 preview **超限（>100）直接 400 拒绝**，不静默截断前 100 | 静默截断会让确认数字与实际执行数不一致——危险动作的确认数字必须可信 | preview 与执行端点同一上限口径（`VALIDATION_BULK_LIMIT_EXCEEDED`） |
| §4.2.2 / §2.4 | 批量归档的逐条权限按 **TASK-009 交付口径（ADMIN 任意 / 其余角色仅创建者本人）**，而非本文规格文字「CONTRIBUTOR+ 任意」 | TASK-009 的 `archive_subtree` 是归档权限的既有事实源（服务内逐条判定）；本文规格文字与其漂移，以服务口径为准免二次授权逻辑 | 非创建者的 CONTRIBUTOR/MEMBER 归档他人任务逐条失败（计入 failed 项）；规格该行随勘误标注 |
| §4.3.3 | 幂等键（`Idempotency-Key`）存储 **Redis 不可用时直通降级**（放行执行、不拒请求） | 幂等是优化保障而非可用性前置；Redis 抖动不应阻断批量操作 | 降级窗口内重复提交会重复执行（Activity epoch 不同、可审计辨识）；WARN 日志记录降级 |
| §4.3.1 / BR-05 | 批量 Activity 行 `comment` 前缀 **`batch:` 并内嵌级联数**（如 `batch: 归档 3 个任务（含 5 个子任务级联）`） | COLLAB-003 折叠行需要稳定 `batch:` 前缀作聚合依据；级联数内嵌让动态流明细一行可读 | 承接 ADR-0017 的 batch 载荷形态；`comment` 为展示字段、不参与幂等键 |

## 七、COLLAB-004 后端（T3-09~11）

## 影响

1. **规格勘误已随本 ADR 回写**（均标注「勘误 2026-09-06（ADR-0020）」）：BOARD-003 §3.5 与 §4.4 ViewStore 段 `?view=` → `?view_id=`（R2）；TASK-011 §3.2 mockup 布局切换器「右侧」→ 左侧（R1）与视图图标示意笔误注（R3）；COLLAB-002 §4.2.2 `reply_to_actor` 来源与父删子留占位条件补注（ADR-0019 决策 1/2 的规格侧落地）；COLLAB-004 BR-11/§3.1 presence 载荷最小化注、§2.5 同键替换 1000 REPLACED 与 4000 语义区分。
2. **遗留项登记**（不阻塞 Sprint-3 关闭）：BOARD-003 列拖拽排序（P3）、COLLAB-001 评论编辑 UI（P3）、表情环形导航（P3 打磨）、生产 nginx `/live/health` 改写（deploy 遗留 + `VITE_LIVE_HEALTH_URL` 覆盖项）、多实例分片广播（live 横扩时）、COLLAB-003 超大库计数 EXPLAIN 换算（bench TODO）。
3. **门禁口径**：G1/G3 口径由本 ADR 固化，`tests/jmeter/sprint-3-bench.py` 为断言载体；后续 Sprint 复用该口径时以本 ADR 为准。
