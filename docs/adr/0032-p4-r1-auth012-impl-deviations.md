# ADR-0032：P4 R1 实现偏差登记（AUTH-012 多租户隔离与风控）

> 登记日期：2026-09-11　|　迭代：P4 R1（AUTH-012 全栈交付）　|　状态：已实现（随收口轮裁决）

## 背景与偏差清单

R1 按 AUTH-012 评审冻结版（含 hifi 原型 FROZEN 2026-09-11）实现治理域全栈（七模型 / 规则引擎 / 17 端点 / 五强制点 / 五 UI 面）过程中，与规格文本存在以下实现偏差，逐项登记（sprint-overview §10.3 纪律：架构偏离先登记再收口）。

### 1. 治理任务队列：默认队列而非独立 governance 队列

- **规格口径**（§4.3 处置隔离）：`execute_action` 独立 `governance` 队列。
- **实现事实**：`risk_ingest` / `execute_action` 走 celery 默认队列——dev worker 只消费默认队列，路由独立队列会使 dev/演示环境风控链路静默断流。
- **裁决**：代码侧不指定 queue；「独立 governance 队列」转为部署期 `task_routes` 配置项，随私有化部署文档（INFRA-006 轮）收口。风险面：治理任务与默认队列任务共享 worker 并发池——治理域任务均为轻量 Redis/DB 操作，无长任务，实际争用可忽略。

### 2. 存储两层判定的层序：租户层前置

- **规格口径**（§2.3/§4.5）：WS 层判定先行（FILE-002 presign 事务内）→ 租户聚合层后判。
- **实现事实**：`check_storage_quota` 挂在 presign 服务调用**之前**（附件与文件库两处）——租户层为 Σ 硬上限，先拒时 WS 层预留同样未落，拒绝语义与「任一层拒绝整体拒绝、不落预留」等价；差别仅在拒绝层归因顺序（细节按实际触发层标注「租户层」）。
- **后续**：FILE-002/RPT-005 出口同批挂接时若需严格层序，可在服务事务内追加租户判定（登记不阻塞）。

### 3. R-03 硬拒挂接范围：本批仅 AUTH-010 审计导出创建路径

- **规格口径**（§4.5 第 5 强制点）：五个出口（AUTH-010 创建+换发 / FILE-002 打包 / RPT-005 快照 / 本文自有出口）。
- **实现事实**：本批挂 `AuditExportView.post`（创建受理前判定）；换发复核、FILE-002 打包、RPT-005 快照出口与「租户审计包 / 风控台账 CSV」自有出口（端点未建）随后续轮挂接。
- **裁决**：R-03 计数与预警/越线事件经审计管道已全量生效（引擎 `on_export`），硬拒挂点按出口落地节奏补齐；known-debt 跟踪。

### 4. 冻结横幅数据通道：响应头而非专用端点

- **规格口径**（§3.4）：租户成员登录看到横幅——通道未定义。
- **实现事实**：治理中间件在冻结租户的**读响应**携带 `X-Tenant-Frozen: 1`（写请求已 409 短路），web 端 axios 响应拦截器写入进程内通道，Topbar 上沿渲染琥珀静默条（法务文案 O8）。
- **取舍**：零额外请求、随任意业务读自动收敛；不带标记的响应即复位（解冻后横幅自动消失）。原型中的 15 分钟倒计时与「缓冲后只读缓存视图」未实现（BR-09 的读写分离已由中间件承载），倒计时属演示增强随 R3 视频轮评估。

### 5. L2 放行的序列化形态

- **规格口径**（§4.2 GovernanceTicket）：「scope 列出的字段在序列化层动态放行（无工单时业务内容字段整体剥离）」。
- **实现事实**：事件序列化默认 L1 字段集（引擎证据快照只落统计与 ID——**源头**保证无业务内容）；approved 未过期工单命中时响应附 `l2_fields`（scope.fields 并集）标注可见性。治理域 API 本身不返回任务标题/文件名等 L2 内容字段——L2 消费发生在运营经业务域端点查看对象时（对象 ID 来自证据快照），后续轮接业务域时按 `l2_fields` 口径对齐。

### 6. 注册钩子自动接受路径的成员配额

- **实现事实**：`check_member_quota` 挂 `InvitationAcceptView`（显式接受）；注册钩子 `accept_pending_invites → _do_accept` 路径仅有既有的 `MAX_WORKSPACE_MEMBERS=100` WS 软限，未挂租户层聚合判定。
- **裁决**：两层语义不同（WS 软限 vs 租户层硬上限）；注册钩子路径补挂随 R2 AUTH-011（成员域）触碰 member service 时顺带——登记不阻塞（私有化默认关闭治理，现网无暴露面）。

### 7. 测试编号覆盖口径

- UT-01~22/25/26 全覆盖；IT-05/07/08/09/10 在 pytest 落地；**IT-01/02/04/06（爬虫全链 / 邻居 P95 漂移 / 两层扣减顺序压测 / 多空间共享池压测）需 broker 与压测环境**，归 jmeter flow 六套与 R1 尾部 perf 套件（known-debt 跟踪）。
- 边界报告产物为 JSON（数据契约齐备），PDF 渲染依赖待选型（known-debt A#6）。

### 8. 测试基建顺带收口（非偏差，留档）

known-debt A#1 三例 e2e 残留的**根因修正**：非顺序依赖——演示工作区 97 个 s3r/s3s 残留成员顶满 `MAX_WORKSPACE_MEMBERS=100` + 清理脚本 NOT NULL FK 表置空炸点失效 → 新注册（带 pending 邀请）自动接受撞软限 409 → 注册事务回滚超时；REG-1 另为评论区受控挂载竞态。修复后三 spec 连跑全绿。权限快照 N+1 批量化（206 → 常数 5）同批收口（known-debt A#2）。
